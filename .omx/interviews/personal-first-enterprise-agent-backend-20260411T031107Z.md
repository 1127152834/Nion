### Clarified target-state answers from the user

## Final clarified answer

### Product model

- 这是一个“个人优先、企业可接入”的双态系统
- 个人模式是默认主态，企业模式是可选扩展态
- 企业后台不是主系统本体，而是个人应用附着的组织协作层

### V1 core

- V1 不先做群聊表层，而是先做企业后台底座
- 底座优先包括：组织、审批、设备绑定、企业身份登录、公开知识同步治理、最小审计链路

### Privacy / ownership model

- 个人私域与企业域必须彻底分仓
- 企业只能接收接入管理数据和用户显式公开的数据
- 管理员只治理企业域资源、组织关系、设备、公开知识与消息元数据
- 管理员永远没有个人私密区穿透权

### Public knowledge model

- “企业公开知识库”只是一层聚合视图
- 真正的 owner 永远是个人
- 公开 / 私密的切换发生在个人本地目录层
- 从公开切回私密时，服务端对应知识也必须被删除

### Enterprise interaction model

- 企业群聊消息可属于企业域
- `@某人的助手` 的交互允许发生在企业协作面
- 但问答正文默认不长期沉淀，只保留必要审计痕迹

## Non-goals

- 不做多企业接入
- 不做跨设备漫游
- 不做企业共享知识协同编辑
- 不做管理员私密区审计后门
- 不做多人共同维护单个个人助手
- 不做自动公开推荐
- 不做企业外部联系人网络
- 本轮不展开具体数据库 schema、API payload、UI 细节

## Decision boundaries

- 默认把个人应用视为第一主体，而不是企业租户
- 未接入企业时，不提前暴露任何公开 / 私密企业语义
- 接入企业后，默认一切知识仍然留在本地私密区
- 只有用户显式公开目录，服务端才接收同步
- 管理员能力上限止于企业域治理，不得跨越到个人私域
- V1 一个安装实例只能接一个企业
- 设备绑定是强约束，不是软提醒
