# Memory Layout Redesign Design

## Goal

把当前记忆模块重构成更工整、更稳定的 A1 左侧导航型布局，减少卡片拼盘感，统一检索区、分区摘要区和详情区的秩序。

## Confirmed Direction

- 整体走 A1 左侧导航型
- 保留低圆角，但避免“大圆角泡泡感”
- 顶部是总览条和快速动作
- 左侧是结构导航，负责稳定页面层级
- 中间是统一高度、统一标题线、统一底部动作位的摘要卡片
- 右侧是 detail inspector 式详情区
- 清理流程仍保留，但作为检索控制台中的动作，不单独占侧栏

## Problems In Current Layout

- 记忆页虽然已经恢复到可视化结构，但主视区仍是“上面一块、下面一块”的拼装状态。
- 摘要卡片、检索控制台、详情面板三者的视觉层级不够统一。
- 当前布局缺少稳定的结构导航，导致用户阅读时没有明确的“当前位置”。
- 摘要卡片仍偏卡片思维，缺少桌面工具应有的秩序感。
- 详情抽屉虽然可用，但页面主区没有被明确组织成“结构地图 + 主工作面 + 检视器”的工作台模型。

## Target Information Architecture

### 1. Overview Rail

顶部保留一条概览区域，分成两部分：

- 左侧：页面标题、简短说明、最后更新时间
- 右侧：快速动作区，放检索和清理入口

概览指标做成低圆角小面板，不追求“展示型 hero”，只承担状态摘要。

### 2. Left Memory Map

左侧增加固定宽度的结构导航区：

- 一级：用户上下文 / 历史背景 / 事实库
- 二级：工作 / 个人 / 近期关注，或近几个月 / 更早上下文 / 长期背景

这个区域的职责不是装饰，而是：

- 显示当前浏览的分区
- 给主区提供稳定的结构锚点
- 压住页面的散乱感

表现上避免大圆角按钮，采用低圆角块或更接近目录的线性分组表达。

### 3. Main Work Surface

中间主区分成两个稳定模块：

- 检索控制台
- 结构化摘要卡片区

检索控制台是一个整块工作面，不再像若干零散小块拼起来。它内部承载：

- 当前记忆搜索
- 过滤器
- 长期记忆结果
- 历史召回结果
- 清理流程入口

结构化摘要卡片区保持三列，但卡片必须：

- 统一最小高度
- 统一头部结构
- 统一元信息位置
- 统一底部动作位

### 4. Detail Inspector

详情不再强调“抽屉突然打开”的感觉，而是朝 inspector 语义收束：

- 标题区更像当前选中对象
- 摘要详情和关联事实分别成块
- 历史类详情保留时间线，但线条和节点都更克制

如果当前技术约束下仍保留 `Sheet` 实现，视觉上也要尽量像右侧检视器，而不是大块 modal panel。

## Visual Language

- 背景保持现有暖白系，不改主色方向
- 大多数容器统一到小圆角，避免过多 16/24px 圆角
- 用边框、分隔线、留白、标题层级建立秩序
- 避免继续堆叠“卡片里的卡片”
- 强调选中态时优先使用边框、浅底色、字重，而不是大面积深色块

## Component Strategy

### Keep

- `MemoryPage` 继续作为统一主视图入口
- `MemoryConsolePanel` 继续承载检索控制台逻辑
- `MemoryDetailDrawer` 继续承载详情视图逻辑

### Refactor

- `MemorySummaryCards` 从“普通统计卡”升级为顶部概览带的一部分
- `MemoryOverviewSections` 改造成带结构秩序的主工作面，不只是简单三列卡片
- `MemoryPage` 负责组装三栏工作台：左侧导航、中部主区、右侧检视器

### Add

- 一个新的左侧结构导航组件，用于记忆地图
- 必要时增加纯展示型的 section header / inspector section 小组件，避免 `MemoryPage` 再次膨胀

## Responsive Behavior

- 桌面端：三栏布局
- 中等宽度：左栏收窄，右侧 inspector 仍保留
- 窄屏：左侧结构导航可折叠到顶部，右侧 inspector 退化为抽屉

本轮优先确保桌面端秩序，移动端只做不破版适配，不做额外复杂交互。

## Cleanup Flow Placement

清理流程保留，但不再做独立侧栏区块。入口放在检索控制台的动作位，风险摘要只保留在弹窗第一步。

## Success Criteria

- 页面第一眼能看出清晰的三层结构：结构导航 / 主工作面 / 详情检视器
- 主区不会再显得“东一块西一块”
- 摘要卡片在有内容和空状态下都整齐
- 详情面板和主区语言一致，不再像外来层
- 保留现有功能，不牺牲交互完整性
