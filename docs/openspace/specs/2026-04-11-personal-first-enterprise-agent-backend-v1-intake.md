# Personal-First Enterprise Agent Backend V1 Intake

## Why this exists

当前产品是单机个人 agent 助手。目标不是把它替换成企业主系统，而是在保留个人模式完整价值的前提下，为它追加一个受控的企业接入层。

这意味着系统必须同时满足两件事：

- 在未接入企业时，它仍然是一套完整的私人助理产品
- 在接入企业后，它能够成为企业协作网络中的一个安全节点

## Core product stance

### 1. Personal-first

- 个人应用是第一主体
- 企业后台是可选接入层，不是产品根
- 用户可以永远不登录企业，只使用私人模式

### 2. Enterprise is opt-in

- 设置中存在“启用企业后台”的开关
- 用户输入企业后台 `base_url`
- 应用先探测该地址是否有效
- 只有在显式启用并完成申请 / 登录后，企业能力才会出现

### 3. Privacy is structural

- 未接入企业时，不暴露“公开 / 私密”企业语义
- 接入企业后，知识默认仍全部私密
- 只有用户手动将目录标记为公开，服务端才允许同步
- 管理员永远不能读取个人私密笔记、私密 wiki、私密会话

## V1 objective

V1 的目标不是先做群聊表层，而是先打通企业后台底座，使系统具备“安全接入企业”的主链。

## V1 success definition

V1 成立的标准是：

1. 企业接入主链路跑通
2. 个人 / 企业数据边界真正生效

### 1. Enterprise onboarding mainline

- 用户可启用企业后台并输入 `base_url`
- 应用可探测该地址是否为有效企业后台
- 未登录时进入申请流程
- 企业不允许自注册，只允许申请制
- 申请信息至少包括：用户名、姓名、组织架构、职位
- 管理员可审批或拒绝，并附带拒绝理由
- 申请人能实时收到审批结果
- 登录必须绑定当前安装设备
- 首次登录必须强制修改默认密码

### 2. Data boundary mainline

- 默认只上传身份与设备信息
- 笔记 / wiki 默认不离开本地
- 只有用户显式公开的目录会同步到服务端
- 企业公开知识库只是个人公开知识的聚合视图
- 管理员只治理企业域资源和公开数据，不得访问私密区
- 群聊里 `@某人的助手` 的回答正文不做长期保存，只留必要审计痕迹

## V1 system modules

### Personal app side

- 私人模式开关与企业接入开关
- 企业 `base_url` 探测
- 企业申请 / 登录 / 首次改密流程
- 本地目录公开 / 私密标记
- 本地到服务端的公开知识同步器

### Enterprise backend side

- 组织、成员、职位、审批流
- 企业身份认证与会话
- 设备绑定
- 公开知识聚合索引
- 企业消息与最小审计

### Later capabilities built on top of V1

- 企业群聊
- 群聊里 `@用户`
- 群聊里 `@用户助手`
- 基于企业公开知识聚合的代答

## Hard constraints

- 单安装实例在 V1 里只能接一个企业
- 不允许跨设备漫游
- 不允许多人共同维护一个个人助手
- 不存在企业共享编辑知识库
- 不允许管理员代管个人私密知识
- 不自动推荐把私密目录改成公开
- 不做企业外部联系人网络

## Key design consequences

### 1. Knowledge is owned by the individual

企业公开知识库不是企业写作空间，而是个人公开知识的索引合集。真正的 owner 永远是个人，不是企业。

### 2. Enterprise data must be modeled separately from private data

个人私域、企业协作数据、公开知识索引，必须是三个清晰对象，不能混用一个“知识库”概念糊过去。

### 3. Security is not a later add-on

申请制、设备绑定、首次改密、私域隔离、最小留痕，这些都不是上线后再补，而是 V1 架构前提。

## Planning questions for the next stage

- 申请态用户如何安全接收拒绝通知
- 设备绑定使用什么凭证和解绑流程
- `base_url` 探针和企业版本协商协议怎么定义
- 目录级公开 / 私密切换如何做增量同步与撤回删除
- 企业群聊消息和 `@助手` 最小审计痕迹如何分表建模

进入实施规划阶段，把这份 intake 展开为后台子系统规划：

- 企业接入状态机
- 审批与通知机制
- 设备绑定与企业身份安全模型
- 公开知识同步协议
- 群聊 / `@助手` / 最小审计对象模型
